Lektion 9: Inline-Modus ​

Lernziel ​

Dein Bot antwortet auf Inline-Abfragen: Nutzer tippen @dein_bot Stichwort in einem beliebigen Chat und wählen ein Ergebnis aus. Du kannst den Inline-Modus bei @BotFather einschalten, inline_query beantworten, Ergebnisse in Seiten aufteilen, Rückmeldungen zu gewählten Ergebnissen auswerten und mit einer Taste in den Chat mit dem Bot wechseln.

Neu im gemeinsamen Modul apps/telegram-client sind die Klasse Inline (Ergebnisse und Antwort bauen) und zwei Tasten in Tastaturen, die in den Inline-Modus wechseln. Die Anwendung ist der Inline-Such-Bot in apps/inline-such-bot, ein kleines Beispiel steht in examples/09-inline-modus.

Erklärung ​

Was der Inline-Modus ist. Nutzer rufen deinen Bot nicht im Chat mit dem Bot auf, sondern tippen in irgendeinem Chat, auch in Gruppen und Kanälen, den Benutzernamen des Bots und eine Abfrage. Dein Bot liefert eine Liste von Ergebnissen. Tippt der Nutzer auf eines, wird es sofort an den Chatpartner gesendet, vom Nutzer, nicht vom Bot. Das Eingabefeld wird geleert. Die Nachricht trägt den Hinweis „über @dein_bot". In der Nachricht steht das im Feld via_bot.

Einschalten. Der Inline-Modus ist standardmäßig aus. Sende /setinline an @BotFather und gib einen Platzhaltertext an, den der Nutzer nach dem Botnamen im Eingabefeld sieht, zum Beispiel „Methode suchen". Zwei weitere Schalter:

BotFather-BefehlWirkung
/setinlineschaltet den Inline-Modus ein, setzt den Platzhalter
/setinlinefeedbackdu bekommst chosen_inline_result, wenn jemand ein Ergebnis auswählt. Bei beliebten Bots kommt viel zusammen, dort lässt sich ein Anteil (1/10, 1/100, 1/1000) einstellen.
/setinlinegeoder Client fragt den Nutzer nach dem Standort, er kommt im Feld location der Abfrage

Die Abfrage. Jeder getippte Buchstabe kann ein Update inline_query auslösen. Du musst inline_query in allowed_updates anfordern, sonst bleibt der Bot stumm. Das Objekt hat diese Felder:

FeldInhalt
iddie ID, mit der du antwortest
fromder Nutzer
queryder Text der Abfrage, bis zu 256 Zeichen. Leer, wenn nur der Botname getippt wurde: Hier bieten sich Standardergebnisse an.
offsetdie Seite, die der Client gerade will (siehe unten). Beim ersten Mal leer.
chat_typesender (Chat mit dem Nutzer selbst), private, group, supergroup oder channel. Fehlt bei Abfragen aus geheimen Chats.

Antworten mit answerInlineQuery. Pflicht sind inline_query_id und results, eine Liste mit höchstens 50 Ergebnissen. Eine leere Liste ist erlaubt. Weitere Parameter:

ParameterBedeutung
cache_timewie lange Telegram die Antwort aufbewahrt und gleiche Abfragen selbst beantwortet, in Sekunden. Standard: 300. Zum Ausprobieren ist ein kleiner Wert bequemer.
is_personaltrue, wenn die Antwort nur für diesen Nutzer gilt. Sonst sieht jeder Nutzer mit derselben Abfrage dieselbe Antwort aus dem Zwischenspeicher.
next_offsetder Wert, den der Client als offset schickt, wenn der Nutzer weiter nach unten scrollt. Leer heißt: es gibt keine weiteren Ergebnisse. Höchstens 64 Bytes.
buttoneine Taste über den Ergebnissen (siehe unten)

Ergebnistypen. Das Feld type bestimmt, wie ein Ergebnis aussieht. Es gibt article (Titel und Beschreibung), photo, gif, mpeg4_gif, video, audio, voice, document, location, venue, contact, game und sticker. Für Medien gibt es zwei Varianten: mit einer URL (Telegram lädt sie) oder als …Cached… mit einer file_id einer Datei, die schon bei Telegram liegt (zum Beispiel InlineQueryResultCachedPhoto). Jedes Ergebnis braucht eine eindeutige id mit 1 bis 64 Bytes.

Die meisten Typen haben ihren Inhalt schon in sich. Ein article bringt dagegen nur Titel und Beschreibung mit. Was in den Chat gesendet wird, steht in input_message_content. Das kann Text sein (message_text, 1 bis 4096 Zeichen, mit parse_mode und link_preview_options), ein Standort, ein Ort, ein Kontakt oder eine Rechnung. Dieser Inhalt kann auch anders sein als das, was in der Liste steht, im Beispiel ist es Name, Beschreibung und Link.

Seiten. Bei vielen Treffern lieferst du nur die erste Seite und setzt next_offset, zum Beispiel auf die Nummer des nächsten Treffers. Scrollt der Nutzer ans Ende, schickt der Client dieselbe Abfrage noch einmal, jetzt mit diesem Wert als offset. Gibt es nichts mehr, setzt du next_offset auf einen leeren Text. Der offset ist Eingabe vom Client, behandle ihn wie jede Eingabe: Das Beispiel nimmt bei allem, was keine Zahl ab 0 ist, den Anfang.

Die Taste über den Ergebnissen. Mit button zeigst du über den Ergebnissen (oder statt ihnen) eine Taste. Sie hat entweder ein start_parameter oder eine web_app (Lektion 11). Mit start_parameter öffnet ein Tipp den Chat mit dem Bot und sendet dort /start <parameter>. Der Parameter hat 1 bis 64 Zeichen aus A-Z, a-z, 0-9, _ und -, es ist derselbe Deep Link wie in Lektion 5. So bietest du zum Beispiel eine Anmeldung an, bevor der Bot personalisierte Ergebnisse liefert. Den Rückweg bietet eine Inline-Taste mit switch_inline_query: Sie öffnet die Chatauswahl und setzt @dein_bot <Abfrage> ins Eingabefeld. switch_inline_query_current_chat macht das im aktuellen Chat.

Rückmeldung: chosen_inline_result. Mit /setinlinefeedback bekommst du ein Update, wenn jemand ein Ergebnis auswählt. Es enthält result_id (die id deines Ergebnisses), from und query. Wegen des Zwischenspeichers können mehr Auswahlen ankommen als Abfragen. Hängt an dem Ergebnis eine Inline-Tastatur, steht zusätzlich inline_message_id darin. Damit kannst du die Nachricht später ändern (Lektion 7), chat_id und message_id gibt es hier nicht.

Tipps und Fallen:

  • Antworte schnell. Der Nutzer tippt weiter, jede Abfrage wird gleich wieder überholt. Eine zu späte Antwort lehnt Telegram mit einem Fehler ab. Der Beispiel-Bot fängt ihn ab und macht weiter.
  • Leere Abfrage nicht vergessen. Sie ist der erste Eindruck. Gib Standard- oder Beliebtheitsergebnisse zurück, im Beispiel die am häufigsten gewählten.
  • Texte ohne parse_mode sind sicher. Willst du HTML oder Markdown verwenden, müssen Namen aus deiner Datenquelle maskiert werden (Lektion 4).
  • Ob ein Ergebnis gewählt wurde, erfährt dein Bot nur über chosen_inline_result, und das nur mit eingeschaltetem Feedback.
  • Pro Token darf nur ein Programm getUpdates aufrufen (Fehler 409), wie bei allen Beispielen.

Methoden dieser Lektion

  • answerInlineQuery (Inline-Modus)

curl ​

Du brauchst die ID einer Abfrage. Tippe dazu @dein_bot test in einem Chat und lies das Update:

bash
API="https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN"

curl "$API/getUpdates" -d allowed_updates='["inline_query"]'

# Antwort mit einem Ergebnis; die Abfrage-ID steht im Update
curl "$API/answerInlineQuery" -H "Content-Type: application/json" -d '{
  "inline_query_id": "DIE_ID_AUS_DEM_UPDATE",
  "cache_time": 5,
  "results": [{
    "type": "article",
    "id": "1",
    "title": "Hallo",
    "description": "Sendet einen Gruß",
    "input_message_content": {"message_text": "Hallo aus dem Inline-Modus!"}
  }]
}'

Antworte zügig nach dem Tippen, sonst ist die Abfrage schon veraltet. Zum Ausprobieren per curl ist ein Bot mit exec:java darum bequemer.

Java ​

Ein Ergebnis und die Antwort bauen. Inline.artikel prüft die Grenzen (ID bis 64 Bytes, Text 1 bis 4096 Zeichen), Inline.antwort die Anzahl:

java
/**
 * Ein Ergebnis vom Typ {@code article}: ein Eintrag mit Titel und Beschreibung in der Ergebnisliste. Tippt der
 * Nutzer darauf, wird {@code text} als normale Nachricht in den Chat gesendet.
 */
public static ObjectNode artikel(String id, String titel, String beschreibung, String text) {
    int bytes = id.getBytes(StandardCharsets.UTF_8).length;
    if (bytes < 1 || bytes > 64) {
        throw new IllegalArgumentException("Die ID eines Ergebnisses muss 1 bis 64 Bytes lang sein, ist aber " + bytes);
    }
    if (text.isEmpty() || text.length() > 4096) {
        throw new IllegalArgumentException("Der Nachrichtentext braucht 1 bis 4096 Zeichen");
    }
    ObjectNode ergebnis = TelegramClient.parameter().put("type", "article").put("id", id).put("title", titel);
    if (beschreibung != null && !beschreibung.isEmpty()) {
        ergebnis.put("description", beschreibung);
    }
    ergebnis.putObject("input_message_content").put("message_text", text);
    return ergebnis;
}
java
/** Die Parameter von {@code answerInlineQuery}: Anfrage-ID und bis zu 50 Ergebnisse. Weitere Felder setzt der Aufrufer. */
public static ObjectNode antwort(String anfrageId, List<ObjectNode> ergebnisse) {
    if (ergebnisse.size() > MAX_ERGEBNISSE) {
        throw new IllegalArgumentException("Höchstens " + MAX_ERGEBNISSE + " Ergebnisse, übergeben wurden " + ergebnisse.size());
    }
    ObjectNode parameter = TelegramClient.parameter().put("inline_query_id", anfrageId);
    ArrayNode liste = parameter.putArray("results");
    ergebnisse.forEach(liste::add);
    return parameter;
}

Der kleinste Inline-Bot antwortet auf jede Abfrage mit einem Ergebnis „Senden: <Text>":

java
public static void main(String[] args) throws Exception {
    TelegramClient client = TelegramClient.ausUmgebung();
    System.out.println("Inline-Echo läuft, Strg+C beendet");
    // Ohne "inline_query" in allowed_updates bekommt der Bot keine Abfragen.
    new UpdatePoller(client, List.of("inline_query")).laufen(new InlineEcho(client).alsHandler());
}
java
void behandle(JsonNode update) throws IOException, InterruptedException {
    JsonNode abfrage = update.path("inline_query");
    if (abfrage.isMissingNode()) {
        return;
    }
    String text = abfrage.path("query").asText().strip();
    // Bei leerer Abfrage gibt es nichts zu senden: eine leere Liste ist eine gültige Antwort.
    List<ObjectNode> ergebnisse = text.isEmpty()
            ? List.of()
            : List.of(Inline.artikel("echo", "Senden: " + text, "Schickt deinen Text in den Chat", text));
    ObjectNode antwort = Inline.antwort(abfrage.get("id").asText(), ergebnisse);
    // Telegram merkt sich Antworten standardmäßig 300 Sekunden. Zum Ausprobieren ist eine kurze Zeit bequemer.
    antwort.put("cache_time", 5);
    client.aufrufen("answerInlineQuery", antwort);
}

bash

Anwendung: Inline-Such-Bot ​

Der Bot durchsucht eine lokale Datenquelle, die Datei katalog.tsv mit 30 Methoden der Bot API (Name, Tabulator, Beschreibung). Tippst du @dein_bot photo, bekommst du sendPhoto, bei @dein_bot send sind es elf Treffer auf zwei Seiten. Ein Tipp sendet Name, Beschreibung und Link zur Doku in den Chat.

Die Datenquelle und die Suche. Treffer im Namen kommen vor Treffern in der Beschreibung, ein genauer Name ganz nach vorn:

java
/**
 * Sucht ohne Beachtung der Groß- und Kleinschreibung. Die Reihenfolge: genauer Name, Name beginnt mit dem Suchwort,
 * Name enthält es, nur die Beschreibung enthält es. Innerhalb einer Stufe bleibt die Reihenfolge des Katalogs.
 */
public List<Eintrag> suche(String suchwort) {
    String wort = suchwort.strip().toLowerCase(Locale.ROOT);
    if (wort.isEmpty()) {
        return List.of();
    }
    return eintraege.stream()
            .filter(e -> stufe(e, wort) < 4)
            .sorted(Comparator.comparingInt(e -> stufe(e, wort)))
            .toList();
}

private static int stufe(Eintrag eintrag, String wort) {
    String name = eintrag.name().toLowerCase(Locale.ROOT);
    if (name.equals(wort)) {
        return 0;
    }
    if (name.startsWith(wort)) {
        return 1;
    }
    if (name.contains(wort)) {
        return 2;
    }
    return eintrag.beschreibung().toLowerCase(Locale.ROOT).contains(wort) ? 3 : 4;
}

Die Abfrage beantworten. Der Bot teilt die Treffer in Seiten zu zehn, setzt next_offset, zeigt die Taste mit dem Deep Link und fängt eine abgelehnte Antwort ab:

java
private void abfrage(JsonNode abfrage) throws IOException, InterruptedException {
    String suchwort = abfrage.path("query").asText().strip();
    int start = seitenStart(abfrage.path("offset").asText());
    // Leere Abfrage: die beliebtesten Einträge. Sonst die Treffer, beste zuerst.
    List<Eintrag> treffer = suchwort.isEmpty() ? nachBeliebtheit() : katalog.suche(suchwort);
    List<Eintrag> seite = treffer.subList(Math.min(start, treffer.size()), Math.min(start + SEITE, treffer.size()));

    ObjectNode antwort = Inline.antwort(abfrage.get("id").asText(), seite.stream()
            .map(e -> Inline.artikel(e.name(), e.name(), e.beschreibung(), e.nachricht()))
            .toList());
    antwort.put("cache_time", CACHE_SEKUNDEN);
    // Es gibt weitere Treffer? Dann sagt next_offset dem Client, womit er die nächste Seite anfordert. Leer = Ende.
    antwort.put("next_offset", start + SEITE < treffer.size() ? String.valueOf(start + SEITE) : "");
    // Die Taste über den Ergebnissen öffnet den Chat mit dem Bot und sendet dort "/start <parameter>".
    antwort.putObject("button")
            .put("text", seite.isEmpty() ? "Nichts gefunden - Hilfe im Chat" : "Im Chat mit dem Bot suchen")
            .put("start_parameter", seite.isEmpty() ? "hilfe" : "suche");
    try {
        client.aufrufen("answerInlineQuery", antwort);
    } catch (TelegramException e) {
        // Der Nutzer tippt weiter, eine alte Abfrage kann abgelaufen sein. Das ist kein Grund, den Bot zu stoppen.
        System.err.println("Antwort auf die Inline-Abfrage abgelehnt: " + e.getMessage());
    }
}

/** Der Offset kommt vom Client. Alles, was keine Zahl ab 0 ist, zählt als Anfang. */
static int seitenStart(String offset) {
    try {
        return Math.max(0, Integer.parseInt(offset));
    } catch (NumberFormatException e) {
        return 0;
    }
}

private List<Eintrag> nachBeliebtheit() {
    // sorted ist stabil: bei gleicher Anzahl bleibt die Reihenfolge des Katalogs.
    return katalog.alle().stream()
            .sorted(Comparator.comparingInt((Eintrag e) -> -gewaehlt.getOrDefault(e.name(), 0)))
            .toList();
}

Der Chat mit dem Bot. Die Taste über den Ergebnissen führt per Deep Link hierher. Der Bot erklärt die Suche und bietet zwei Tasten an, die in den Inline-Modus wechseln:

java
private void nachricht(JsonNode nachricht) throws IOException, InterruptedException {
    Optional<Befehl> befehl = Befehl.aus(nachricht, eigenerName);
    if (befehl.isEmpty() && Befehl.beginntMitBefehl(nachricht)) {
        return; // Befehl an einen anderen Bot
    }
    long chatId = nachricht.path("chat").path("id").asLong();
    ObjectNode parameter = TelegramClient.parameter().put("chat_id", chatId)
            .put("text", antworttext(befehl.map(Befehl::name).orElse(""), befehl.map(Befehl::argumente).orElse("")));
    parameter.set("reply_markup", Tastaturen.inline(List.of(List.of(
            Taste.inlineHier("Hier suchen", ""), Taste.inlineInAnderemChat("In einem anderen Chat suchen", "")))));
    client.aufrufen("sendMessage", parameter);
}

/** Bei der Taste "Im Chat mit dem Bot suchen" kommt "/start suche" an, bei "Nichts gefunden" "/start hilfe". */
String antworttext(String befehl, String parameter) {
    String hilfe = "Ich suche Methoden der Bot API. Tippe in einem beliebigen Chat @" + eigenerName
            + " und ein Stichwort, zum Beispiel \"photo\". Ein Tipp auf ein Ergebnis sendet es in den Chat.";
    if (befehl.equals("start") && parameter.equals("hilfe")) {
        return "Dazu habe ich nichts gefunden. Versuche ein anderes Stichwort, den Namen oder einen Teil der "
                + "Beschreibung.\n\n" + hilfe;
    }
    return hilfe;
}

bash

  -Dexec.mainClass=telegram.lernen.apps.inlinesuche.InlineSuchBot
  1. Tippe in einem Chat @dein_bot photo und wähle sendPhoto aus.
  2. Tippe @dein_bot send. Es erscheinen zehn Treffer, beim Scrollen kommt der elfte (zweite Seite).

Übung ​

Baue einen Inline-Rechner: @dein_bot 12+30 liefert genau ein Ergebnis „12 + 30 = 42". Ein Tipp sendet die Rechnung in den Chat. Unterstütze +, -, * und /. Bei einer Eingabe, die keine Aufgabe ist, oder einer Division durch 0 antwortet der Bot mit einer leeren Liste.

Lösung
java
private static final Pattern AUFGABE =
        Pattern.compile("(-?\\d{1,15}(?:\\.\\d{1,15})?)\\s*([-+*/])\\s*(-?\\d{1,15}(?:\\.\\d{1,15})?)");

/** Rechnet "12+30" aus. Leer, wenn die Eingabe keine Aufgabe ist oder durch 0 geteilt wird. */
static Optional<String> rechnen(String eingabe) {
    Matcher m = AUFGABE.matcher(eingabe.strip());
    if (!m.matches()) {
        return Optional.empty();
    }
    BigDecimal a = new BigDecimal(m.group(1));
    BigDecimal b = new BigDecimal(m.group(3));
    BigDecimal ergebnis;
    switch (m.group(2)) {
        case "+" -> ergebnis = a.add(b);
        case "-" -> ergebnis = a.subtract(b);
        case "*" -> ergebnis = a.multiply(b);
        default -> {
            if (b.signum() == 0) {
                return Optional.empty();
            }
            ergebnis = a.divide(b, MathContext.DECIMAL64);
        }
    }
    String zahl = ergebnis.signum() == 0 ? "0" : ergebnis.stripTrailingZeros().toPlainString();
    return Optional.of(m.group(1) + " " + m.group(2) + " " + m.group(3) + " = " + zahl);
}

static void antworten(TelegramClient client, JsonNode abfrage) throws IOException, InterruptedException {
    List<ObjectNode> ergebnisse = rechnen(abfrage.path("query").asText())
            .map(text -> List.of(Inline.artikel("ergebnis", text, "Antippen sendet die Rechnung in den Chat", text)))
            .orElse(List.of());
    ObjectNode antwort = Inline.antwort(abfrage.get("id").asText(), ergebnisse);
    antwort.put("cache_time", 5);
    client.aufrufen("answerInlineQuery", antwort);
}

Starten mit -pl examples/09-inline-modus -am -Dexec.mainClass=telegram.lernen.inline.UebungLoesung. Gerechnet wird mit BigDecimal, damit 0.1+0.2 genau 0.3 ergibt.

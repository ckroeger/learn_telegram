Lektion 4: Nachrichten senden ​

Lernziel ​

Du schickst Textnachrichten mit Formatierung, antwortest auf eine bestimmte Nachricht, kennst die wichtigsten Optionen und die Grenzen (4096 Zeichen, Rate-Limits), und du kannst Nachrichten weiterleiten oder kopieren.

Erklärung ​

sendMessage ist die wichtigste Methode. Pflicht sind chat_id und text. Ein Auszug der Parameter:

ParameterBedeutung
chat_idZiel: die Zahl des Chats oder @benutzername eines öffentlichen Kanals oder einer Supergruppe. Chats mit Nutzern haben positive, Gruppen und Kanäle negative Zahlen.
text1 bis 4096 Zeichen (nach dem Auswerten der Formatierung)
parse_modeHTML oder MarkdownV2, siehe unten
entitiesFormatierung als Liste von Bereichen statt parse_mode
link_preview_optionsz. B. {"is_disabled":true} schaltet die Link-Vorschau ab
disable_notificationSendet ohne Ton
protect_contentVerbietet Weiterleiten und Speichern der Nachricht
reply_parametersAntwort auf eine Nachricht, z. B. {"message_id":7}
reply_markupTasten unter oder statt der Tastatur, siehe Lektion 5

Die Methode gibt die gesendete Message zurück, vor allem mit ihrer message_id. Die brauchst du, um später zu antworten, zu bearbeiten oder zu löschen.

Formatierung. Mit parse_mode liest Telegram Auszeichnungen im Text. Es gibt zwei empfohlene Wege:

  • HTML (parse_mode: "HTML"): <b>fett</b>, <i>kursiv</i>, <u>, <s>, <code>, <pre>, <a href="…">Link</a>, <blockquote> und <tg-spoiler>. Außerhalb von Tags müssen nur drei Zeichen ersetzt werden: & durch &amp;, < durch &lt; und > durch &gt;. Andere benannte Entitäten außer &quot; gibt es nicht.
  • MarkdownV2 (parse_mode: "MarkdownV2"): *fett*, _kursiv_, `code` und weitere. Hier müssen die Zeichen _ * [ ] ( ) ~ ` > # + - = | { } . ! mit einem vorangestellten Backslash geschützt werden, wenn sie normaler Text sein sollen. Das trifft Satzzeichen wie . und ! ständig.

Für Text, den dein Programm zusammenbaut (Nutzereingaben, Zahlen, Dateinamen), ist HTML deshalb der sicherere Weg: Du ersetzt drei Zeichen und bist fertig. Lässt du das weg, antwortet Telegram mit einem Fehler wie „can't parse entities", und die Nachricht kommt nicht an. Das alte Format Markdown gibt es nur noch aus Kompatibilitätsgründen.

Entitäten lassen sich verschachteln (<b>fett <i>und kursiv</i></b>), <pre> und <code> aber nicht mit anderen Auszeichnungen mischen. Verlinke einen Nutzer mit tg://user?id=<id> nur innerhalb eines Links, in einfachem Text funktioniert das nicht.

Antworten. reply_parameters mit der message_id macht die Nachricht zur Antwort, die Telegram mit einem Zitat der Originalnachricht anzeigt. Mit quote lässt sich ein Teil des Originals zitieren, er muss genau darin vorkommen.

Chat-Aktion. sendChatAction mit action: "typing" zeigt „schreibt …" an. Der Status hält höchstens 5 Sekunden und verschwindet, sobald eine Nachricht vom Bot ankommt. Nutze das nur, wenn die Antwort spürbar dauert. Andere Aktionen: upload_photo, upload_document, record_voice und weitere, je nachdem, was der Nutzer gleich bekommt.

Weiterleiten oder kopieren. forwardMessage leitet eine Nachricht weiter, sie behält den Hinweis auf den ursprünglichen Absender. copyMessage kopiert sie, ohne diesen Hinweis, und liefert nur die neue message_id. Servicenachrichten und Nachrichten mit geschütztem Inhalt (protect_content) lassen sich nicht weiterleiten. Beide brauchen from_chat_id (Quelle), chat_id (Ziel) und message_id.

Lange Texte. Mehr als 4096 Zeichen lehnt Telegram ab. Teile den Text selbst, am besten an Zeilenumbrüchen. Bei HTML darfst du nie mitten in einem Tag teilen, das Beispiel unten teilt nur reinen Text.

Grenzen beim Senden. Eine Massennachricht an viele Nutzer ist auf etwa 30 Nutzer pro Sekunde begrenzt. Darüber antwortet Telegram mit HTTP 429 und retry_after, wie in Lektion 3. Verteile größere Versendungen über längere Zeit.

Typische Fehler (der Wortlaut kann sich ändern, prüfe error_code):

error_codeBeispiel für descriptionUrsache
400can't parse entitiesFormatierung fehlerhaft, bei HTML fehlt ein Escape
400message is too longmehr als 4096 Zeichen
400chat not foundfalsche chat_id
403bot was blocked by the userder Nutzer hat den Bot blockiert
429Too Many Requests: retry after Nzu viele Anfragen

curl ​

Setze zuerst deine Chat-ID, die du aus dem Quick-Start kennst:

bash
CHAT=DEINE_CHAT_ID
API="https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN"

# einfacher Text
curl "$API/sendMessage" -H "Content-Type: application/json" \
  -d "{\"chat_id\":$CHAT,\"text\":\"Hallo\"}"

# mit HTML
curl "$API/sendMessage" -H "Content-Type: application/json" \
  -d "{\"chat_id\":$CHAT,\"text\":\"<b>fett</b> und <i>kursiv</i>, 1 &lt; 2\",\"parse_mode\":\"HTML\"}"

# Antwort auf die Nachricht mit message_id 7
curl "$API/sendMessage" -H "Content-Type: application/json" \
  -d "{\"chat_id\":$CHAT,\"text\":\"Antwort\",\"reply_parameters\":{\"message_id\":7}}"

# "schreibt ..." anzeigen
curl "$API/sendChatAction" -H "Content-Type: application/json" \
  -d "{\"chat_id\":$CHAT,\"action\":\"typing\"}"

Java ​

Das Modul examples/04-nachrichten-senden enthält die Klasse Nachrichten mit einer Methode je Fall. BotApi und TelegramException sind Kopien aus Lektion 2.

Einfacher Text und Formatierung mit HTML. htmlEscape ist der Schutz für alles, was nicht von dir selbst stammt:

java
/** Gibt die gesendete Nachricht zurück, u. a. mit {@code message_id}. */
public JsonNode senden(long chatId, String text) throws IOException, InterruptedException {
    return api.aufrufen("sendMessage", BotApi.parameter().put("chat_id", chatId).put("text", text));
}
java
public JsonNode sendenHtml(long chatId, String html) throws IOException, InterruptedException {
    return api.aufrufen("sendMessage",
            BotApi.parameter().put("chat_id", chatId).put("text", html).put("parse_mode", "HTML"));
}

/** Macht beliebigen Text zu einem sicheren Teil einer HTML-Nachricht. */
public static String htmlEscape(String text) {
    return text.replace("&", "&amp;").replace("<", "&lt;").replace(">", "&gt;");
}

Antworten, Optionen und Chat-Aktion:

java
public JsonNode antworten(long chatId, long nachrichtenId, String text) throws IOException, InterruptedException {
    ObjectNode parameter = BotApi.parameter().put("chat_id", chatId).put("text", text);
    parameter.putObject("reply_parameters").put("message_id", nachrichtenId);
    return api.aufrufen("sendMessage", parameter);
}
java
/** Ohne Ton, ohne Link-Vorschau und gegen Weiterleiten und Speichern geschützt. */
public JsonNode diskret(long chatId, String text) throws IOException, InterruptedException {
    ObjectNode parameter = BotApi.parameter()
            .put("chat_id", chatId)
            .put("text", text)
            .put("disable_notification", true)
            .put("protect_content", true);
    parameter.putObject("link_preview_options").put("is_disabled", true);
    return api.aufrufen("sendMessage", parameter);
}
java
/** Zeigt "schreibt ..." an, bis die nächste Nachricht kommt, höchstens 5 Sekunden. */
public void tippen(long chatId) throws IOException, InterruptedException {
    api.aufrufen("sendChatAction", BotApi.parameter().put("chat_id", chatId).put("action", "typing"));
}

Weiterleiten und Kopieren:

java
/** Leitet eine Nachricht weiter. Sie behält den Hinweis auf den Absender. */
public JsonNode weiterleiten(long zielChat, long vonChat, long nachrichtenId)
        throws IOException, InterruptedException {
    return api.aufrufen("forwardMessage", BotApi.parameter()
            .put("chat_id", zielChat).put("from_chat_id", vonChat).put("message_id", nachrichtenId));
}

/** Kopiert eine Nachricht ohne Hinweis auf das Original und liefert die neue message_id. */
public long kopieren(long zielChat, long vonChat, long nachrichtenId) throws IOException, InterruptedException {
    JsonNode ergebnis = api.aufrufen("copyMessage", BotApi.parameter()
            .put("chat_id", zielChat).put("from_chat_id", vonChat).put("message_id", nachrichtenId));
    return ergebnis.get("message_id").asLong();
}

Lange Texte in Stücke teilen. Die Methode teilt bevorzugt an Zeilenumbrüchen und schneidet nie mitten in ein Emoji, das aus zwei char besteht:

java
/** Schickt einen langen Text als mehrere Nachrichten. */
public List<JsonNode> sendenLang(long chatId, String text) throws IOException, InterruptedException {
    List<JsonNode> gesendet = new ArrayList<>();
    for (String teil : teile(text, MAX_LAENGE)) {
        gesendet.add(senden(chatId, teil));
    }
    return gesendet;
}

/** Teilt bevorzugt an Zeilenumbrüchen, sonst hart nach {@code max} Zeichen, nie mitten in einem Emoji. */
static List<String> teile(String text, int max) {
    List<String> teile = new ArrayList<>();
    String rest = text;
    while (rest.length() > max) {
        int schnitt = rest.lastIndexOf('\n', max);
        if (schnitt > 0) {
            teile.add(rest.substring(0, schnitt));
            rest = rest.substring(schnitt + 1);
        } else {
            schnitt = Character.isLowSurrogate(rest.charAt(max)) ? max - 1 : max;
            teile.add(rest.substring(0, schnitt));
            rest = rest.substring(schnitt);
        }
    }
    if (!rest.isEmpty()) {
        teile.add(rest);
    }
    return teile;
}

Das Programm NachrichtSenden schickt eine kleine Folge: eine Nachricht, eine Antwort darauf, eine HTML-Nachricht mit abgesichertem Nutzertext und die Chat-Aktion.

bash
./mvnw -q compile exec:java -pl examples/04-nachrichten-senden -am \
  -Dexec.mainClass=telegram.lernen.nachrichten.NachrichtSenden \
  -Dexec.args="DEINE_CHAT_ID 'a < b & c'"

In Telegram siehst du vier Dinge: die erste Nachricht, die Antwort als Zitat darauf, Du hast geschrieben: a < b & c mit fettem Anfang und kurz „schreibt …". Das < und das & stehen unverändert im Text, weil htmlEscape sie geschützt hat.

Übung ​

Schicke Quelltext als formatierten Codeblock: Eine Methode soll einen Java-Ausschnitt wie if (a < b && c > d) { return; } als <pre><code class="language-java">…</code></pre> senden. Probiere es zuerst ohne htmlEscape und sieh dir die Fehlermeldung an, dann mit.

Lösung
java
static JsonNode codeSenden(Nachrichten nachrichten, long chatId, String code)
        throws IOException, InterruptedException {
    String html = "<pre><code class=\"language-java\">" + Nachrichten.htmlEscape(code) + "</code></pre>";
    return nachrichten.sendenHtml(chatId, html);
}

Starten mit -Dexec.mainClass=telegram.lernen.nachrichten.UebungLoesung und der Chat-ID als erstem Argument.

Neu in 10.x

Die Beispiele hier nutzen bewusst nur stabile Funktionen. Neu sind:

  • Rich Messages (seit 10.1, sendRichMessage): strukturierte Nachrichten aus Blöcken wie Tabellen, Listen und Medien statt reinem Text.
  • Streaming (sendMessageDraft): zeigt einen Entwurf als zeitlich begrenzte Vorschau von 30 Sekunden, etwa bei KI-Antworten. Danach musst du die fertige Nachricht mit sendMessage senden.
  • Ephemeral Messages (seit 10.2): Nachrichten, die in einer Gruppe nur für einen Nutzer sichtbar sind. Ab 10.3 steuerst du sie mit ephemeral_message_parameters. Das ersetzt receiver_user_id und callback_query_id aus 10.2, ein Breaking Change.

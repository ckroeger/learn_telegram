Lektion 3: Long Polling ​

Lernziel ​

Du holst eingehende Updates mit getUpdates ab, bestätigst sie richtig mit offset und gehst mit Fehlern und Rate-Limits um. Das ist die saubere Version der Schleife aus dem Echo-Bot im Quick-Start.

Erklärung ​

Updates. Alles, was bei deinem Bot ankommt, ist ein Update: eine Nachricht, ein Klick auf einen Button, eine Inline-Anfrage. Jedes Update hat eine fortlaufende update_id und genau ein weiteres Feld, dessen Name den Typ angibt, etwa message, edited_message oder callback_query. Die vollständige Liste der Typen steht in der Doku zum Typ Update.

Es gibt zwei sich ausschließende Wege, Updates zu bekommen: getUpdates (Long Polling, diese Lektion) und Webhooks (Lektion 6). Telegram hält Updates auf dem Server bereit, aber höchstens 24 Stunden.

Long Polling. Dein Programm fragt, Telegram antwortet erst, wenn ein Update da ist, oder nach timeout Sekunden mit einer leeren Liste. Dann fragt dein Programm sofort neu. Das ist effizient und braucht keine erreichbare Adresse. Mit timeout 0 (Short Polling) antwortet Telegram sofort, auch ohne Updates. Das ist nur zum Testen gedacht.

Parameter von getUpdates:

ParameterBedeutung
offsetupdate_id des ersten gewünschten Updates. Ein Update gilt als bestätigt, sobald du mit einem offset fragst, der größer als seine update_id ist. Bestätigte Updates liefert Telegram nicht noch einmal.
limit1 bis 100, Standard 100
timeoutSekunden für Long Polling, Standard 0. Sinnvoll sind z. B. 30.
allowed_updatesListe der Typen, die du bekommen willst

Bestätigen mit offset. Rechne nach jeder Antwort neu: offset = update_id des letzten verarbeiteten Updates + 1. Vergisst du das, bekommst du dieselben Updates immer wieder (die FAQ nennt das „Long polling gives me the same updates again and again").

allowed_updates. Standardmäßig bekommst du alle Typen außer chat_member, message_reaction und message_reaction_count. Willst du diese, musst du sie nennen. Die Einstellung merkt sich Telegram: Lässt du das Feld in einem späteren Aufruf weg, gilt die vorherige weiter. Deshalb sendet unser Beispiel es immer mit, eine leere Liste heißt „Standard". Die Einstellung wirkt nicht auf Updates, die schon vor dem Aufruf entstanden sind, du kannst also kurz noch unerwünschte Typen sehen.

Methoden dieser Lektion

  • getUpdates (Updates empfangen)

curl ​

bash
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getUpdates" \
  -H "Content-Type: application/json" \
  -d '{"timeout":30,"allowed_updates":["message"]}'

Der Aufruf wartet bis zu 30 Sekunden. Schreibe deinem Bot in dieser Zeit etwas, dann kommt die Antwort sofort. Schicke danach denselben Aufruf mit "offset":<update_id+1>, und das bestätigte Update ist weg.

Java ​

Das Modul examples/03-long-polling enthält den Client BotApi aus Lektion 2 als Kopie und neu die Klasse UpdatePoller. Die Schleife holt Updates, übergibt jedes an einen Handler und bestätigt es danach:

java
/** Läuft, bis der Thread unterbrochen wird (dann fliegt eine InterruptedException). */
public void laufen(Consumer<JsonNode> handler) throws InterruptedException {
    while (!Thread.currentThread().isInterrupted()) {
        for (JsonNode update : holeUpdates()) {
            try {
                handler.accept(update);
            } catch (RuntimeException e) {
                // Ein kaputtes Update darf den Bot nicht stoppen und nicht endlos neu geliefert werden.
                System.err.println("Fehler im Handler: " + e);
            }
            // Mit offset = update_id + 1 bestätigen wir dieses und alle früheren Updates.
            offset = update.get("update_id").asLong() + 1;
        }
    }
}

Fehler im Handler

Wirft der Handler eine Exception, wird sie ausgegeben und das Update trotzdem bestätigt. Sonst würde ein einziges „giftiges" Update den Bot endlos blockieren, weil Telegram es immer wieder lieferte. Der Preis: Dieses Update geht verloren. Ob das passt, hängt vom Bot ab.

Die eigentliche Abfrage baut die Parameter, ruft getUpdates auf und fängt die ersten beiden Fehler aus der Tabelle ab. Alle anderen Fehler (409, 401) beenden die Schleife:

java
private JsonNode holeUpdates() throws InterruptedException {
    ObjectNode parameter = BotApi.parameter().put("offset", offset).put("timeout", 30);
    // Immer mitsenden: Fehlt das Feld, gilt die vorherige Einstellung weiter. Eine leere Liste heißt "Standard".
    ArrayNode liste = parameter.putArray("allowed_updates");
    allowedUpdates.forEach(liste::add);
    try {
        return api.aufrufen("getUpdates", parameter);
    } catch (TelegramException e) {
        if (e.retryAfter() > 0) {
            // HTTP 429: so lange warten, wie Telegram verlangt, dann neu fragen.
            schlafen.sekunden(e.retryAfter());
            return JsonNodeFactory.instance.arrayNode();
        }
        throw e;
    } catch (IOException e) {
        // Nur der Typ, nicht die Meldung: sie könnte die URL mit dem Token enthalten.
        System.err.println("Netzwerkfehler (" + e.getClass().getSimpleName() + "), neuer Versuch in 5 Sekunden");
        schlafen.sekunden(5);
        return JsonNodeFactory.instance.arrayNode();
    }
}

Das Programm PollingBot gibt jedes Update in einer Zeile aus:

java
/** Jedes Update hat genau ein Feld außer update_id; sein Name ist der Typ, z. B. "message". */
static String beschreibe(JsonNode update) {
    String typ = typVon(update);
    String text = update.path(typ).path("text").asText("(kein Text)");
    return "Update %d (%s): %s".formatted(update.get("update_id").asLong(), typ, text);
}

private static String typVon(JsonNode update) {
    var namen = update.fieldNames();
    while (namen.hasNext()) {
        String name = namen.next();
        if (!name.equals("update_id")) {
            return name;
        }
    }
    return "?";
}
bash
./mvnw -q compile exec:java -pl examples/03-long-polling -am \
  -Dexec.mainClass=telegram.lernen.longpolling.PollingBot

Schreibe deinem Bot etwas. Es erscheint Update 5 (message): Hallo. Mit Strg+C beendest du das Programm. Alles, was du dem Bot schickst und das kein Text ist (ein Bild, ein Sticker), erscheint mit (kein Text).

Übung ​

Zähle die Nachrichten pro Chat. Fordere dazu mit allowed_updates nur message an und gib nach jedem Update den Stand je Chat-ID aus, z. B. {1234=3}.

Lösung
java
static class NachrichtenZaehler {
    private final Map<Long, Integer> proChat = new TreeMap<>();

    void zaehle(JsonNode update) {
        JsonNode nachricht = update.path("message");
        if (!nachricht.isMissingNode()) {
            proChat.merge(nachricht.path("chat").path("id").asLong(), 1, Integer::sum);
        }
    }

    String stand() {
        return proChat.toString();
    }
}

Starten mit -Dexec.mainClass=telegram.lernen.longpolling.UebungLoesung.

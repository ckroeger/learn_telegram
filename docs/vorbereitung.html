Vorbereitung ​

Einmal einrichten, danach nur noch nachschlagen: Telegram-Konto, ein Bot mit Token und die Werkzeuge. Am Ende steht ein Test, der alles zusammen prüft.

Alle Befehle sind für Bash (Linux, macOS; unter Windows WSL oder Git Bash).

1. Telegram-Konto ​

Du brauchst ein Telegram-Konto mit der App auf dem Handy oder dem Desktop. Bots schreibst du wie normale Kontakte an, deshalb ist die App auch zum Ausprobieren nötig.

2. Einen Bot bei BotFather anlegen ​

BotFather ist der Bot, bei dem man alle anderen Bots anlegt und verwaltet.

  1. Suche in Telegram nach @BotFather (blaues Häkchen) und öffne den Chat.
  2. Sende /newbot.
  3. Wähle einen Namen (frei, z. B. Mein Lern-Bot).
  4. Wähle einen Benutzernamen. Er muss auf bot enden und noch frei sein, z. B. mein_lern_1234_bot.
  5. BotFather antwortet mit dem Token, der aussieht wie 123456:ABC-DEF....

Dieser Bot ist dein Lern-Bot für den Lernpfad und die kleinen Anwendungen. Für Mini App und Login Widget legst du später in deren Kapiteln einen zweiten Bot an.

3. Token ablegen ​

Der Token gehört nicht in den Code, sondern in eine Umgebungsvariable. Alle Beispiele lesen TELEGRAM_BOT_TOKEN.

Pro Terminal-Sitzung:

bash
export TELEGRAM_BOT_TOKEN='123456:ABC-DEF...'

Oder mit einer .env-Datei, die du bei Bedarf einliest. Im Repo liegt die Vorlage .env.example:

bash
cp .env.example .env     # dann den Token in .env eintragen
source .env

.env steht in der .gitignore und wird nie committet.

Wer den Token dauerhaft haben möchte, kann den export in sein Shell-Profil (~/.bashrc) schreiben. Das ist bequem, aber der Token liegt dann im Klartext in einer weiteren Datei.

Windows ohne WSL

In PowerShell gilt für die aktuelle Sitzung: $env:TELEGRAM_BOT_TOKEN='123456:ABC-DEF...'. Alle anderen Befehle dieser Seite sind für Bash gedacht; WSL ist der einfachste Weg.

Der Token ist ein Passwort

Wer den Token kennt, steuert deinen Bot.

  • Er steht bei jedem Aufruf im URL-Pfad (https://api.telegram.org/bot<TOKEN>/getMe). Deshalb loggen die Beispiele die URL nie, und das solltest du in eigenem Code auch nicht tun.
  • Schreibe ihn nie in Code, Commits, Screenshots oder Chat-Nachrichten.
  • Ist er trotzdem geleakt, sende BotFather /revoke. Der alte Token ist sofort ungültig und du bekommst einen neuen.

Übung: einen Token widerrufen ​

Übe den Ernstfall mit einem Wegwerf-Bot, damit du ihn im Notfall kennst.

  1. Lege bei BotFather mit /newbot einen zweiten Bot an, z. B. wegwerf_1234_bot.
  2. Prüfe den Token: curl "https://api.telegram.org/bot<TOKEN>/getMe" liefert "ok":true.
  3. Sende BotFather /revoke und wähle den Wegwerf-Bot. Du bekommst einen neuen Token.
  4. Wiederhole Schritt 2 mit dem alten Token. Jetzt kommt "ok":false mit 401 Unauthorized.
  5. Lösche den Bot mit /deletebot.

Hole dir anschließend den Code der Beispiele:

bash
git clone https://github.com/ckroeger/learn_telegram.git
cd learn_telegram

5. Abschlusstest ​

Dieser Test prüft Werkzeuge, Token und Netz in einem Zug.

bash
./mvnw -v
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getMe"

Die erste Zeile zeigt Maven und dein JDK 21. Die zweite antwortet mit dem Profil deines Bots:

json
{"ok":true,"result":{"id":123456,"is_bot":true,"first_name":"Mein Lern-Bot","username":"mein_lern_1234_bot", ...}}

Siehst du "ok":true, bist du bereit für den Quick-Start.

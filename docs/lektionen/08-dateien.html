Lektion 8: Dateien ​

Lernziel ​

Du schickst Dateien auf allen drei Wegen (file_id, URL, Upload), nimmst Dokumente und Fotos entgegen und lädst sie herunter. Du kennst die Größengrenzen und weißt, warum ein Dateiname vom Absender nie unbesehen verwendet werden darf.

Der Upload und der Download stecken ab dieser Lektion im gemeinsamen Modul apps/telegram-client. Die Anwendung ist ein Datei-Bot in examples/08-dateien.

Erklärung ​

Drei Wege, eine Datei zu senden. Die Methoden sendDocument, sendPhoto, sendAudio, sendVideo und weitere nehmen dieselben Möglichkeiten im Parameter für die Datei (document, photo und so weiter):

WegSoGrenze
file_idEine Datei, die schon bei Telegram liegt, wird nur über ihre ID angegeben. Kein Upload. Empfohlen.keine
URLTelegram lädt die Datei selbst von einer öffentlichen Adresse.Fotos 5 MB, alles andere 20 MB. Der MIME-Typ muss stimmen. sendDocument per URL klappt derzeit nur für PDF und ZIP.
UploadDu schickst die Datei mit multipart/form-data, wie ein Browser ein Formular mit Datei.Fotos 10 MB, alles andere 50 MB

sendPhoto verlangt zusätzlich: höchstens 10 MB, Breite plus Höhe höchstens 10000 Pixel und ein Seitenverhältnis von höchstens 20. Eine Beschriftung (caption) hat 0 bis 1024 Zeichen.

Regeln für file_id.

  • Der Typ lässt sich nicht ändern: Ein Foto kann nicht als Dokument und ein Video nicht als Foto erneut gesendet werden.
  • Sie gilt nur für den Bot, der sie bekommen hat, und lässt sich nicht an einen anderen Bot weitergeben.
  • Eine Datei kann mehrere gültige file_id haben.
  • Die file_unique_id bleibt über die Zeit und über Bots hinweg gleich, taugt aber nicht zum Senden oder Herunterladen. Du nutzt sie, um dieselbe Datei wiederzuerkennen.
  • Ein Foto per file_id erneut zu senden, schickt alle seine Größen.

Dateien empfangen. Schickt jemand dem Bot eine Datei, steht sie in der Nachricht:

  • message.document hat file_id, file_unique_id, file_name, mime_type und file_size. Name und Typ sind „wie vom Absender angegeben".
  • message.photo ist eine Liste von PhotoSize, dieselbe Aufnahme in mehreren Auflösungen mit width, height und file_size. Nimm die größte.
  • Eine Beschriftung steht in caption. Es gibt weitere Felder für Audio, Video, Sprachnachrichten und Sticker nach demselben Muster.

Herunterladen. Zwei Schritte. Zuerst getFile mit der file_id, das ein File-Objekt mit dem file_path liefert. Dann ein GET auf https://api.telegram.org/file/bot<token>/<file_path>. Bots dürfen Dateien bis 20 MB herunterladen. Der Link ist mindestens eine Stunde gültig, danach rufst du getFile erneut auf. getFile liefert Name und MIME-Typ nicht unbedingt mit: Merke sie dir aus der Nachricht.

Vorsicht beim Herunterladen.

  • Der Link enthält den Token. Gib ihn nie aus und schick ihn nie an Nutzer weiter.
  • Der Dateiname kommt vom Absender. Heißt eine Datei ../../.ssh/authorized_keys und du speicherst sie unter genau diesem Namen, schreibt der Absender in Verzeichnisse außerhalb deines Ordners (Path Traversal). Nimm nur den letzten Namensteil, ersetze Sonderzeichen und prüfe, dass der Zielpfad im Zielordner liegt.
  • Zwei Dateien mit demselben Namen dürfen sich nicht überschreiben. Das Beispiel stellt die file_unique_id voran.
  • Prüfe die Größe vor dem Herunterladen (file_size) und führe empfangene Dateien nie automatisch aus.

Wie ein Upload aufgebaut ist. Bei multipart/form-data besteht die Anfrage aus mehreren Teilen, getrennt durch eine zufällige Grenze (boundary). Jeder Parameter ist ein Teil mit name, die Datei ein Teil mit name und filename. Daraus folgt:

  • JSON als Körper geht nicht, denn Binärdaten passen nicht hinein.
  • Zahlen und Wahrheitswerte gehen als Text. Objekte und Listen wie reply_markup schickst du als JSON-Text im Feld.
  • Große Dateien sollten gestreamt und nicht in den Speicher geladen werden.
  • Der Dateiname steht in einer Kopfzeile. Enthält er " oder einen Zeilenumbruch, könnte ein Angreifer die Anfrage verändern (Header-Injection). Deshalb werden diese Zeichen als %22, %0D und %0A geschrieben.

curl ​

curl -F schickt multipart/form-data und liest die Datei mit @:

bash
API="https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN"
CHAT=DEINE_CHAT_ID

# Upload einer Datei von der Festplatte
curl "$API/sendDocument" -F chat_id=$CHAT -F caption="Mein Bericht" -F document=@bericht.pdf

# per URL (nur PDF und ZIP bei sendDocument)
curl "$API/sendDocument" -d chat_id=$CHAT -d document=https://beispiel.example/datei.pdf

# per file_id (steht in einer empfangenen Nachricht)
curl "$API/sendDocument" -d chat_id=$CHAT -d document=FILE_ID

# Herunterladen: erst getFile, dann der Pfad aus der Antwort
curl "$API/getFile" -d file_id=FILE_ID
curl -o heruntergeladen.pdf "https://api.telegram.org/file/bot$TELEGRAM_BOT_TOKEN/documents/file_12.pdf"

Java ​

Hochladen. TelegramClient.hochladen nimmt die Parameter wie bei aufrufen und dazu eine oder mehrere Dateianhang-Objekte. Ein Dateianhang ist eine Datei von der Festplatte (sie wird beim Senden gelesen) oder aus Bytes im Speicher:

java
/**
 * Ruft eine Methode mit Dateien auf, z. B. {@code sendDocument}. Statt JSON geht der Aufruf als
 * {@code multipart/form-data}: die Parameter als Textfelder, jede Datei als eigener Teil.
 */
public JsonNode hochladen(String methode, ObjectNode parameter, Dateianhang... dateien)
        throws IOException, InterruptedException {
    Multipart multipart = Multipart.aus(parameter, List.of(dateien));
    HttpRequest anfrage = HttpRequest.newBuilder(URI.create(apiUrl + methode))
            .header("Content-Type", multipart.contentType())
            .timeout(Duration.ofMinutes(5))
            .POST(multipart.koerper())
            .build();
    HttpResponse<String> antwort = http.send(anfrage, HttpResponse.BodyHandlers.ofString());
    JsonNode json = JSON.readTree(antwort.body());
    if (!json.path("ok").asBoolean()) {
        throw new TelegramException(json);
    }
    return json.get("result");
}

Der Körper entsteht in Multipart. Die Datei wird dabei mit BodyPublishers.ofFile gestreamt:

java
/** Parameter als Textfelder, Dateien als Teile mit Dateiname. Dateien werden gestreamt, nicht geladen. */
static Multipart aus(ObjectNode parameter, List<Dateianhang> dateien) throws IOException {
    Multipart multipart = new Multipart();
    for (Iterator<Map.Entry<String, JsonNode>> felder = parameter.fields(); felder.hasNext(); ) {
        Map.Entry<String, JsonNode> feld = felder.next();
        // Zahlen und Wahrheitswerte als Text, Objekte und Listen (z. B. reply_markup) als JSON-Text.
        JsonNode wert = feld.getValue();
        multipart.text(feld.getKey(), wert.isValueNode() ? wert.asText() : wert.toString());
    }
    for (Dateianhang datei : dateien) {
        multipart.datei(datei);
    }
    multipart.teile.add(BodyPublishers.ofString("--" + multipart.grenze + "--" + ZEILENENDE));
    return multipart;
}

Herunterladen. Der Pfad wird in eine URL eingesetzt, deshalb sind nur Pfadzeichen erlaubt:

java
/**
 * Lädt eine Datei herunter, deren {@code file_path} {@code getFile} geliefert hat. Telegram erlaubt das für
 * Dateien bis 20 MB. Die Adresse enthält den Token, sie darf nie ausgegeben werden.
 */
public void herunterladen(String dateiPfad, Path ziel) throws IOException, InterruptedException {
    // Der Pfad kommt von Telegram, aber er wird in eine URL eingesetzt: nichts anderes als Pfadzeichen zulassen.
    if (!dateiPfad.matches("[A-Za-z0-9_./-]+") || dateiPfad.contains("..") || dateiPfad.startsWith("/")) {
        throw new IllegalArgumentException("Ungültiger file_path");
    }
    HttpRequest anfrage = HttpRequest.newBuilder(URI.create(dateiUrl + dateiPfad))
            .timeout(Duration.ofMinutes(5)).GET().build();
    HttpResponse<InputStream> antwort = http.send(anfrage, HttpResponse.BodyHandlers.ofInputStream());
    try (InputStream eingang = antwort.body()) {
        if (antwort.statusCode() != 200) {
            throw new IOException("Download fehlgeschlagen: HTTP " + antwort.statusCode());
        }
        Files.copy(eingang, ziel, StandardCopyOption.REPLACE_EXISTING);
    }
}

Senden: eine Datei von der Festplatte, eine im Speicher erzeugte Datei, eine bei Telegram vorhandene Datei per file_id und ein Foto per URL:

java
/** Lädt eine Datei von der Festplatte hoch. Dokumente dürfen bis 50 MB groß sein. */
public static JsonNode dokumentHochladen(TelegramClient client, long chatId, Path datei, String beschriftung)
        throws IOException, InterruptedException {
    return client.hochladen("sendDocument",
            TelegramClient.parameter().put("chat_id", chatId).put("caption", beschriftung),
            Dateianhang.von("document", datei));
}

/** Erzeugt eine Datei im Speicher und lädt sie hoch, ganz ohne Festplatte. */
public static JsonNode berichtHochladen(TelegramClient client, long chatId, String dateiname, String text)
        throws IOException, InterruptedException {
    return client.hochladen("sendDocument", TelegramClient.parameter().put("chat_id", chatId),
            Dateianhang.von("document", dateiname, "text/plain; charset=utf-8", text.getBytes(java.nio.charset.StandardCharsets.UTF_8)));
}

/** Sendet eine Datei, die schon bei Telegram liegt: nur die file_id, kein Upload, keine Größengrenze. */
public static JsonNode dokumentErneutSenden(TelegramClient client, long chatId, String fileId, String beschriftung)
        throws IOException, InterruptedException {
    return client.aufrufen("sendDocument", TelegramClient.parameter()
            .put("chat_id", chatId).put("document", fileId).put("caption", beschriftung));
}

/** Telegram lädt das Foto selbst von der Adresse: bis 5 MB, und die Adresse muss öffentlich sein. */
public static JsonNode fotoPerUrlSenden(TelegramClient client, long chatId, String url, String beschriftung)
        throws IOException, InterruptedException {
    return client.aufrufen("sendPhoto", TelegramClient.parameter()
            .put("chat_id", chatId).put("photo", url).put("caption", beschriftung));
}

Empfangen. Ein Dokument ist ein Objekt, ein Foto eine Liste. Bei Fotos zählt die Größe mit den meisten Pixeln:

java
/** Liest ein Dokument oder Foto aus einer Nachricht. Bei einem Foto zählt die größte der gelieferten Größen. */
public static Optional<DateiInfo> info(JsonNode nachricht) {
    JsonNode dokument = nachricht.path("document");
    if (dokument.isObject()) {
        return Optional.of(new DateiInfo("document", dokument.path("file_id").asText(),
                dokument.path("file_unique_id").asText(), dokument.path("file_name").asText(null),
                dokument.path("mime_type").asText(null), dokument.path("file_size").asLong(-1), 0, 0));
    }
    JsonNode foto = groessteFoto(nachricht.path("photo"));
    if (foto != null) {
        return Optional.of(new DateiInfo("photo", foto.path("file_id").asText(),
                foto.path("file_unique_id").asText(), null, "image/jpeg", foto.path("file_size").asLong(-1),
                foto.path("width").asInt(), foto.path("height").asInt()));
    }
    return Optional.empty();
}

/** Ein Foto kommt als Liste von {@code PhotoSize} in mehreren Auflösungen. Die größte hat die meisten Pixel. */
static JsonNode groessteFoto(JsonNode groessen) {
    JsonNode groesste = null;
    for (JsonNode groesse : groessen) {
        long pixel = groesse.path("width").asLong() * groesse.path("height").asLong();
        if (groesste == null || pixel > groesste.path("width").asLong() * groesste.path("height").asLong()) {
            groesste = groesse;
        }
    }
    return groesste;
}

Speichern. Hier steckt die Sicherheit: Größe vor dem Download prüfen, einen harmlosen Namen bilden, die file_unique_id voranstellen und kontrollieren, dass der Zielpfad im Ordner liegt:

java
/**
 * Lädt eine Datei in den Ordner. Der Dateiname kommt vom Absender und ist daher nicht vertrauenswürdig:
 * {@link #sicherName} macht daraus einen harmlosen Namen, und die {@code file_unique_id} verhindert,
 * dass zwei gleich benannte Dateien sich überschreiben.
 *
 * @return der Pfad der gespeicherten Datei
 */
public static Path herunterladen(TelegramClient client, DateiInfo datei, Path ordner)
        throws IOException, InterruptedException {
    if (datei.groesse() > MAX_DOWNLOAD) {
        throw new IOException("Datei ist größer als das Limit von 20 MB");
    }
    JsonNode dateiInfo = client.aufrufen("getFile", TelegramClient.parameter().put("file_id", datei.fileId()));
    Files.createDirectories(ordner);
    String name = datei.uniqueId() + "_" + sicherName(datei.name(), datei.typ());
    Path ziel = ordner.resolve(name).normalize();
    if (!ziel.startsWith(ordner.normalize())) {
        throw new IOException("Zielpfad liegt außerhalb des Ordners");
    }
    client.herunterladen(dateiInfo.path("file_path").asText(), ziel);
    return ziel;
}

/** Macht einen vom Absender gelieferten Namen zu einem harmlosen: ohne Pfad, ohne Sonderzeichen. */
static String sicherName(String name, String ersatz) {
    String nurName = name == null ? "" : name.replace('\\', '/');
    nurName = nurName.substring(nurName.lastIndexOf('/') + 1);
    nurName = nurName.replaceAll("[^\\p{L}\\p{N}._ -]", "_");
    nurName = nurName.replaceAll("^[.\\s]+", "");
    if (nurName.length() > 100) {
        nurName = nurName.substring(nurName.length() - 100);
    }
    return nurName.isBlank() ? ersatz : nurName;
}

Der Datei-Bot speichert, was du ihm schickst, in den Ordner empfangen/ (mit DATEI_ORDNER änderbar), beschreibt die Datei und schickt sie per file_id zurück. /datei lädt eine im Speicher erzeugte Textdatei hoch:

bash
./mvnw -q compile exec:java -pl examples/08-dateien -am \
  -Dexec.mainClass=telegram.lernen.dateien.DateiBot

Schicke ihm ein Dokument, ein Foto und /datei. Du bekommst die Datei zurück, und in empfangen/ liegt sie unter einem Namen wie AgADxx_notiz.txt. Scheitert das Speichern, schickt der Bot die Datei trotzdem zurück.

Dokument oder Foto?

Schickst du ein Bild über „Foto", komprimiert Telegram es und liefert mehrere Größen. Schickst du dieselbe Datei als „Datei", bleibt sie unverändert und kommt als document an. Der Bot behandelt beide Fälle.

Übung ​

Der Bot soll auf ein Foto mit einem Satz antworten, zum Beispiel „Foto 1280x720, 85 KB (größte von 3 Größen)". Schreibe dafür eine Methode, die aus der Liste photo einer Nachricht diesen Satz macht.

Lösung
java
/** Zum Beispiel "Foto 1280x720, 85 KB (größte von 3 Größen)". */
static String fotoBeschreibung(JsonNode groessen) {
    JsonNode groesste = Dateien.groessteFoto(groessen);
    if (groesste == null) {
        return "Kein Foto";
    }
    long kilobyte = Math.round(groesste.path("file_size").asLong() / 1024.0);
    return "Foto %dx%d, %d KB (größte von %d Größen)".formatted(groesste.path("width").asInt(),
            groesste.path("height").asInt(), kilobyte, groessen.size());
}

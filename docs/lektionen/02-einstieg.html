Lektion 2: Einstieg ​

Lernziel ​

Du rufst die Bot API aus Java auf, liest die Antwort mit Jackson und weißt, woran du Erfolg und Fehler erkennst. Danach gibst du deinem Bot ein Profil.

Erklärung ​

Aufbau eines Aufrufs. Jede Methode der Bot API ist eine URL: https://api.telegram.org/bot<TOKEN>/<METHODE>. Der Methodenname unterscheidet nicht zwischen Groß- und Kleinschreibung, das Muster getMe ist nur Konvention. Parameter lassen sich auf vier Wegen übergeben: als URL-Query, als application/x-www-form-urlencoded, als application/json oder (nur für Datei-Uploads) als multipart/form-data. Wir nehmen JSON, außer beim Hochladen von Dateien.

Aufbau der Antwort. Telegram antwortet immer mit JSON und einem Feld ok:

json
{"ok":true,"result":{...}}
{"ok":false,"error_code":401,"description":"Unauthorized"}

Bei ok:true steht das Ergebnis in result. Bei ok:false stehen error_code und description da, manchmal auch parameters mit Hinweisen zur Behebung, etwa retry_after bei zu vielen Anfragen. Der Text von description kann sich ändern, verlasse dich im Code auf ok und error_code, nicht auf den Wortlaut.

getMe braucht keine Parameter und liefert das Profil des Bots. Damit lässt sich prüfen, ob der Token stimmt, deshalb steht es am Anfang jedes Programms.

JSON lesen mit Jackson. Ab jetzt verwenden die Beispiele Jackson 2 (ObjectMapper). readTree liest JSON in einen JsonNode-Baum, ohne dass du Klassen für Telegrams Antworten schreiben musst. get("name") liefert null, wenn das Feld fehlt. path("name") liefert stattdessen einen leeren Knoten, auf dem weitere Aufrufe gefahrlos sind. Für Felder, die fehlen dürfen, nimmst du path.

Das Bot-Profil. Mit setMy… und getMy… pflegst du, was Nutzer von deinem Bot sehen:

MethodeWirkungLänge
setMyNameAnzeigename0 bis 64 Zeichen
setMyDescriptionBeschreibung, erscheint im leeren Chat vor dem ersten Start0 bis 512 Zeichen
setMyShortDescriptionKurzbeschreibung, steht auf der Profilseite und beim Teilen des Bots0 bis 120 Zeichen

Alle drei nehmen optional language_code (zwei Buchstaben, ISO 639-1) für sprachabhängige Texte. Ohne ihn gilt der Text für alle, für die es keinen eigenen gibt. Ein leerer String entfernt den Eintrag.

curl ​

bash
# Profil lesen
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getMe"

# Kurzbeschreibung setzen und zurücklesen
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setMyShortDescription" \
  -H "Content-Type: application/json" \
  -d '{"short_description":"Mein Lern-Bot"}'
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getMyShortDescription"

Java ​

Das Modul examples/02-einstieg besteht aus einem kleinen Client und zwei Programmen. Der Client BotApi sendet einen Aufruf als JSON-POST, prüft ok und gibt result zurück. Bei ok:false wirft er eine TelegramException:

java
public JsonNode aufrufen(String methode, ObjectNode parameter) throws IOException, InterruptedException {
    HttpRequest anfrage = HttpRequest.newBuilder(URI.create(apiUrl + methode))
            .header("Content-Type", "application/json")
            .timeout(Duration.ofSeconds(60))
            .POST(HttpRequest.BodyPublishers.ofString(parameter.toString()))
            .build();
    HttpResponse<String> antwort = http.send(anfrage, HttpResponse.BodyHandlers.ofString());

    JsonNode json = JSON.readTree(antwort.body());
    if (!json.path("ok").asBoolean()) {
        throw new TelegramException(json);
    }
    return json.get("result");
}
TelegramException
java
package telegram.lernen.einstieg;

import com.fasterxml.jackson.databind.JsonNode;

/** Telegram hat mit {@code "ok":false} geantwortet. */
public class TelegramException extends RuntimeException {

    private final int errorCode;
    private final int retryAfter;

    TelegramException(JsonNode antwort) {
        super("Telegram-Fehler %d: %s".formatted(antwort.path("error_code").asInt(), antwort.path("description").asText()));
        this.errorCode = antwort.path("error_code").asInt();
        // Bei HTTP 429 sagt Telegram, wie viele Sekunden man warten soll.
        this.retryAfter = antwort.path("parameters").path("retry_after").asInt(0);
    }

    public int errorCode() {
        return errorCode;
    }

    public int retryAfter() {
        return retryAfter;
    }
}

Das erste Programm fragt mit getMe nach dem Profil:

java
static String profil(BotApi api) throws IOException, InterruptedException {
    JsonNode bot = api.aufrufen("getMe");
    return "Bot %s (@%s), id %d".formatted(
            bot.get("first_name").asText(),
            bot.get("username").asText(),
            bot.get("id").asLong());
}

Starte es im Hauptordner des Repos:

bash
./mvnw -q compile exec:java -pl examples/02-einstieg -am \
  -Dexec.mainClass=telegram.lernen.einstieg.WerBinIch

Die Ausgabe sieht so aus: Bot Mein Lern-Bot (@mein_lern_1234_bot), id 123456.

Was -pl und -am tun

-pl examples/02-einstieg wählt das Modul, -am nimmt die Module mit, von denen es abhängt (hier das Test-Support-Modul). Zum Starten braucht das Beispiel es nicht, Maven löst aber alle Abhängigkeiten auf.

Das zweite Programm setzt die Kurzbeschreibung und liest sie zur Kontrolle zurück:

java
static String kurzbeschreibungSetzen(BotApi api, String text) throws IOException, InterruptedException {
    api.aufrufen("setMyShortDescription", BotApi.parameter().put("short_description", text));
    return api.aufrufen("getMyShortDescription").get("short_description").asText();
}
bash
./mvnw -q compile exec:java -pl examples/02-einstieg -am \
  -Dexec.mainClass=telegram.lernen.einstieg.BotProfil -Dexec.args="Mein Lern-Bot"

Öffne danach in Telegram die Profilseite deines Bots: Die Kurzbeschreibung steht dort.

Die Umgebungsvariable TELEGRAM_API_URL

BotApi.ausUmgebung() liest neben dem Token optional TELEGRAM_API_URL. Sie ist für die Tests da, die statt Telegram einen Fake ansprechen. Im Alltag setzt du sie nicht, der Standard ist https://api.telegram.org.

Übung ​

Setze die lange Beschreibung deines Bots mit setMyDescription (bis 512 Zeichen) und lies sie mit getMyDescription zurück. Die Beschreibung erscheint in einem Chat, in dem noch nichts geschrieben wurde: Lösche den Chat mit deinem Bot und öffne ihn neu, um sie zu sehen.

Lösung
java
static String beschreibungSetzen(BotApi api, String text) throws IOException, InterruptedException {
    api.aufrufen("setMyDescription", BotApi.parameter().put("description", text));
    return api.aufrufen("getMyDescription").get("description").asText();
}
